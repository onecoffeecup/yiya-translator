# 本地文字诊断

## 普通用户：运行检测与导出诊断包

新版「运行设置 → 诊断与反馈」提供「运行检测」「导出诊断包…」和「通过邮件反馈…」。用户可导出 `yiya-diagnostics-日期时间.json` 后通过聊天反馈，也可选择邮件反馈：先保存诊断包，再通过 macOS 邮件共享服务打开邮件草稿，自动填入收件人 `yiyatranslator@163.com`、主题、问题描述模板及 JSON 附件，由用户检查并点击发送。应用不自动发送邮件，也不打开公开反馈页。GitHub 的旧 0.1.0 安装包没有这个入口，需要安装包含本次改动的新版。

- 常规诊断只在内存保留本次运行最近最多 5 分钟、600 条事件；繁忙时只保留较近的记录。刷新窗口、开始翻译和运行中每 5 秒会更新检测结果。
- 诊断包包括 App 版本、构建号、macOS 版本、进程架构及 Rosetta 状态、权限检查结果、窗口 ID／大小／类型、选中的窗口和实际显示目标，以及截图／OCR／翻译请求的成功状态、数量、耗时和数字错误码。
- QuickTime、OBS、译芽及其他应用只按类型标记；不导出窗口标题、其他应用名称、截图、OCR 原文、译文、接口地址、API Key、设置文件或学习数据库。旧文字诊断文件和崩溃文件不自动混入这个包。
- 检测区分权限未生效、只能列出自身窗口、QuickTime 运行但没有可见画面窗口、目标已关闭、截图失败、OCR 空结果和翻译请求失败。结论是排查线索，不保证自动修复；恢复成功后不继续用旧失败覆盖当前状态。
- 点击导出时固定当时的状态；随后选择保存位置不会改变已生成的报告。取消保存不会写文件，保存失败会提示换位置重试。单独导出成功后在 Finder 中显示文件；邮件反馈则打开邮件草稿。邮件功能不可用、取消或失败时，诊断包仍保留，可通过网页邮箱手动添加附件发送。邮件服务完成不代表收件人已收到，需在邮件应用中确认发送状态。
- 运行记录随应用退出清空，不用于还原上一次崩溃。发生问题时应先导出，再退出应用；若已经闪退，需另行提供系统崩溃报告。

诊断内容采用独立白名单；实现见 `objc/FYRuntimeDiagnostics.h/.m` 与 `objc/FYDiagnosticsUI.inc`。基础测试运行 `bash scripts/run-diagnostics-tests.sh`；原生交互、权限回退和窄宽布局测试为 `DiagnosticsInteractionTests`。

## 开发者：按需采集文字链路

用于定位选中窗口的 OCR、模式判定、稳定等待、句子身份、翻译缓存及字幕更新之间的关系。仅记录已经发生的处理，不额外采集或发起翻译。

主源码调用点和构建入口已接入，并通过 Apple Silicon / Intel 构建及无网络测试。只有加载这次新构建的应用才会产生日志；仅修改仓库不会更新已安装或正在运行的应用。

## 隐私与边界

- 默认关闭；启用后包含所选窗口的 OCR 原文、识别框和译文。这些是本地敏感文本，分享前应检查。
- 不保存截图，不读取配置或密钥，不记录认证头、原始 HTTP 包、提示词、完整缓存键或错误描述。字段采用白名单。
- 最长 300 秒，默认 120 秒；单份日志不超过 1 MiB，达到上限提前停止。单条文本过长会截断并标记。
- 每次写入检查开关与有效期；停止或过期后的异步回调不会继续记录。重新启用采用新的会话 ID，旧回调不会混入新会话。
- 目录权限 0700、文件权限 0600；不上传日志。
- 不使用 `FUYI_DIAG` 或 `/tmp/fuyi-diag-armed`。旧诊断开关另有保存截图的行为。

## 控制命令（需要运行已接入此模块的新构建）

在项目目录运行：

```sh
python3 scripts/translation-trace.py start --seconds 120
python3 scripts/translation-trace.py status
python3 scripts/translation-trace.py stop
```

`start` 会清除上一份文字日志，再开启一个新会话；需要保留旧日志时应先自行复制。命令不启动应用、不操作窗口、不请求翻译。可在短时复现完成后立即 `stop`。

日志位于 `/tmp/yiya-text-trace-<当前用户数字 UID>/events.jsonl`，控制命令会打印确切路径。启用后首次被跟踪的处理周期才创建日志。`status` 只显示开关时效和文件大小，不能证明当前运行的安装版已加载代码。

## 日志含义

每行是一个 JSON 对象，含 `time_unix_ms`、`session`、`cycle`、`window_id`、运行代次；翻译路径增加 `request_id`，可关联身份、缓存、网络完成和应用结果。

- `ocr`：已有 OCR 的过滤后第一遍、精读合并结果和模态区域结果；`ocr_lines` 含文本与归一化框，坐标原点在左下。它不是额外识别请求，也不包含图像。
- `mode`、`stable`、`skip`：自动判别、候选计数、等待稳定、重复文字和节流等跳过原因。不会额外调用稳定判定。
- `dialogue`：提取的对白、身份关联后的实际原文、句子 ID 和版本。`identity_request_id` 是学习协调器身份中的编号，与本次诊断 `request_id` 分开。
- `cache`：对白及贴译的命中/未命中；命中时没有 `request_submit` 属于正常行为。
- `request_submit`：已有网络任务真正提交前的源文；`http_complete` 只含状态码、耗时和数字错误码；`request_complete` 记录解码成功的译文或数字错误码，失败响应正文不入日志。
- `caption_apply/drop`、`inline_apply/drop`：应用字幕/贴译或丢弃的原因。`caption_apply` 表示已调用字幕更新，`visible` 区分其浮窗当时是否可见；`inline_apply` 表示已交给既有贴译渲染入口，不能据此断言每个面板都可见。

这些日志不直接探测 QuickTime 控制条是否显示。复现时需要记下控制条出现/消失的大致时间，再与同一窗口的 OCR 行及翻译链路对照。两帧截图或模拟测试都不替代实际事件时间线。

## 无网络检查

```sh
bash scripts/run-translation-trace-tests.sh
```

测试使用独立临时目录和可控时钟，不触碰真实开关，不创建应用窗口、不抓屏、不读取用户设置或数据库、不调用网络。覆盖默认关闭、会话/周期/请求关联、字段白名单、动态停止、超时、重新启用、大小上限、权限和符号链接拒绝。集成测试调用真实 timer/cache/翻译响应代码，使用合成图、预定 OCR 和内存 HTTP mock，对比开关前后的请求与字幕结果，并检查缓存命中、过期窗口响应丢弃和贴译路径。

## 加载到安装版

2026-10-07 更新的 v0.2.0 附件已包含此模块。更新本机安装版时，先正常退出译芽，再按首次打开说明替换应用；从源码构建则可运行 `bash scripts/install-app.sh`，它会备份并替换原应用。安装脚本不是诊断开关的一部分。新版打开后，文字开关可动态启停，无需为每次采样重启。
