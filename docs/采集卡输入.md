# 采集卡输入

译芽新增「识别输入源」：除了原有的**窗口截图**，还可以直接读取**外接视频采集卡**的画面。
输入源只决定 OCR 从哪里取图；**字幕仍然显示在你选中的 QuickTime／OBS 窗口上**，两者分开选择。

## 为什么需要它

原来译芽截取 QuickTime 窗口再 OCR。QuickTime 的录制控制条会浮在画面上，遮住中间那行日文，
于是同一句对白会被读成不同文本、反复请求翻译。现场日志
（`.build/translation-trace-integration/live-session-20261005T103518.857493Z/events.jsonl`）里可以看到：

| 轮次 | 送进翻译的原文 | 结果 |
| --- | --- | --- |
| 第 1 次请求 | `あ、またやってス\nミヨは、\nすごく当たるんだから！\nね？` | 中间行被截成残句「ミヨは、」 |
| 第 2 次请求 | `花椿\nあ、またやって、\nミヨは、\n…` | 仍是残句，句子编号不同、缓存未命中 |
| 第 3 次请求 | `あ、またやってる。\nミヨは占いに凝ってんの。\n…` | 恢复完整句 |

录制条一出现，中间行就掉字；它淡出后又变回完整句。**这不是相似度或缓存问题**，
所以本期的做法是从输入端避开录制条：直接读采集卡信号，画面里本来就没有 QuickTime 控件。

## 怎么用

1. 「运行设置」→「画面来源」→「识别输入源」选 **采集卡**。
2. 点「刷新设备」。列表只会出现**外接采集设备**（例如 `USB Video`），
   不会自动选中，也不会出现内置摄像头、iPhone 接力相机、Desk View 或任何音频设备。
3. 选择设备 → 点「重连采集卡」（或直接点「开始翻译」）：
   **第一次会自动弹出相机权限提示**（这一步仍然由你点击触发，不会开机就弹），点「允许」后自动继续连接；
   如果之前已明确拒绝过，系统不会再弹，状态行会提示你，并出现一个「打开相机权限设置」按钮
   （系统设置 → 隐私与安全性 › 相机 里允许译芽）。
4. 状态行会显示当前识别输入源、是否连上、收到多少帧、按限速丢了多少旧帧。
5. 运行设置里的「游戏画面所在窗口」仍然选择显示游戏画面的 QuickTime 或 OBS 窗口
   （采集卡设备提供识别画面，这里选的是译文跟随的目标，两者是分开的），然后点「开始翻译」。

界面按模式收起：选「窗口截图」时不会显示采集卡那一堆控件，只留一行说明；
采集卡专属控件、状态行和「采集卡说明」折叠只在选「采集卡」时出现。状态行开头始终写着当前识别输入源。

采集卡模式**不需要屏幕录制权限**，因为译芽不再去截屏。

### 什么时候要点「重连采集卡」

- 拔插采集卡、切换 HDMI 信号源、设备被其他程序独占之后；
- 状态行显示「已断开」「采集卡不可用」「采集卡出错」时。

断开后译芽会立刻释放采集会话并丢弃手里的帧，**不会继续用旧帧翻译**；重连成功后从新画面继续。

## 字幕窗与 OBS 全屏预览／预览投影

现场实测（窗口层级时间线）发现两个原因，都已修正：

1. **被压住**：OBS 的预览／投影窗用的是 **层级 101**（`NSPopUpMenuWindowLevel`），
   而译芽字幕窗原来固定用层级 3（`NSFloatingWindowLevel`），所以字幕被盖在下面。
   现在字幕窗、收起小条、查句窗、AI 窗和贴译面板的层级**跟随目标应用自己的最高层级**（上限 102），
   目标应用用普通窗口时仍然保持层级 3。
2. **被隐藏**：进入投影全屏后，OBS 主窗口和 QuickTime 窗口都会离开"屏幕上的窗口"列表
   （全屏窗口在独立空间里），原来的前后台规则只看"选中的那个窗口在不在屏幕上"，
   于是误判成"目标不在前台"就直接把字幕窗藏起来。
   现在规则改为：**目标应用在前台，且它在屏幕上还有别的窗口**（投影窗就是）就算前台；
   目标应用不在前台、或整个应用在屏幕上没有窗口（切到别的空间／全部最小化）仍然隐藏。

贴译位置也跟着**实际承载游戏画面的窗口**走：在 OBS 编辑器预览 ↔ 全屏投影之间切换时，
译芽会认出画面现在在哪个窗口（编辑器 / 窗口投影 / 全屏投影）并按那个窗口重新贴译，
不需要重新翻译，也不会要求你逐张拖动补救。应用自己的设置窗口、属性面板等小弹窗不会
被当成分身目标；同时存在多个投影、无法确定时，旧贴译会先隐藏并提示重新选择，而不是猜一个窗口。
「游戏画面所在窗口」的下拉框默认只列推荐的窗口（OBS／QuickTime／全屏游戏），
点「显示全部窗口」可以选择浏览器、模拟器等其它窗口；当前窗口关闭后会明确提示重新选择。

想自己核查窗口层级，可以用只读诊断：

```bash
scripts/dump-window-layers.sh              # 列一次屏幕上的窗口与层级
scripts/dump-window-layers.sh --watch 120  # 连续记录 2 分钟，供对照
```

## 「看原句 / 问 AI / 引用最新句」的语义（本期核对过）

这三个动作**语义不同，没有统一修改**：

| 动作 | 原文从哪里来 | 采集卡模式下的行为 |
| --- | --- | --- |
| 看原句 | `resolveLatestStudyIdentity`：当前已显示/已记录的那一句（绑定字幕） | 不变 |
| 问 AI | 查句面板固定的 `quickSentenceSource`（绑定字幕） | 不变 |
| 引用最新句 | `resolveLatestStudySentence` → **重新识别当前画面** | 改为读取**采集卡最新帧**，而不是截窗 |

只有「引用最新句」是"重新识别当前画面"。它的语义保持不变（仍然是"看现在这一眼"），
但画面来源跟随「识别输入源」——否则采集卡模式下点它会重新把 QuickTime 录制条拍进去。
采集卡没有画面时它会明确提示「采集卡暂无画面」，不会沿用旧画面；识别期间输入源或窗口变了则提示重新引用。

## 明确限制（有意为之，不是缺陷）

- **采集卡模式不做原位贴译。** 视频像素坐标和屏幕坐标没有可靠换算：OBS 预览区可能只占窗口的一部分，
  按整个窗口尺寸硬贴会把中文放到错误位置。因此界面类画面（菜单、选项）的译文改在悬浮字幕窗里按顺序显示，
  对白与选项合并成一块送入字幕窗；**窗口截图模式的原位贴译行为完全不变**。
- **不承诺与 QuickTime 逐帧同步。** 两者来自同一路信号，但缓冲、OCR 和网络翻译都有延迟。
  本期目标是消除内部串句（残句、旧帧、旧请求乱序），字幕延迟是否可接受要按现场实测判断。
- **不与 QuickTime／OBS 抢设备格式。** 译芽刻意不调用 `lockForConfiguration`、不写 `activeFormat`、
  不设定分辨率，避免干扰它们正在进行的预览。
- **只采视频。** 不加任何音频输入，也不读取屏幕音频。
- **不做设备回退。** 权限被拒绝、设备不存在或被占用时只报告原因；绝不会悄悄改开内置或手机摄像头。
- **一次只服务一台设备。** 换设备或重连都会先释放旧会话；运行中切到采集卡却起不来
  （权限被拒／设备缺失／被占用）时，译芽会**停止本次运行**并说明原因，而不是继续显示"正在运行"。
- **「翻译当前界面」、实时循环与「引用最新句」跟随识别输入源**，采集卡模式从采集帧识别，不因界面快照额外要求屏幕录制。
- v0.2.0 更新附件支持手动 OCR 范围：先定位或校准实际视频画面，再框选其中要翻译的部分。视频画面校准决定坐标映射，OCR 范围决定哪些像素参与识别，两者不同。详见 [识别范围](识别范围.md)。

## 关键实现

| 关注点 | 做法 |
| --- | --- |
| 会话生命周期 | `objc/FYCaptureCardInput.m`：`startWithDeviceUniqueID:` / `stop` / 断开通知 / 运行错误通知都会释放输入输出 |
| 只列采集卡 | 设备发现只用外接视频类型，并排除内置广角、Continuity Camera、Desk View；再用名称/型号兜底排除 iPhone、iPad |
| 有界缓存 | `FYCaptureCardFrameSlot`：只保留**最新一帧**，按最短间隔（默认 0.1 秒）丢弃多余帧并计数，永不排队 |
| 内部串句 | 会话代次 `sessionEpoch` 在开始/停止/断开/出错时自增；`timerFired:` 记下本轮代次，回调时比对，不等就丢弃 |
| 旧帧 | 没有新帧就跳过整轮，不把上一帧再送一次 OCR；停止/断开立即清空帧槽 |
| 不阻塞主线程 | 采样回调、像素转换都在专用串行队列上；主线程只取结果 |
| 手动重新识别 | 「引用最新句」等"重新识别当前画面"的动作也按识别输入源取图（`objc/FYImmersiveUI.inc`） |
| 可追溯 | 诊断日志（需显式开启）为每轮记录 `input_epoch`、`input_source`，OCR 事件另记 `frame_index`，请求与字幕应用/丢弃都能对上是哪一次采集会话 |

`NSCameraUsageDescription` 已加入 App 的 `Info.plist`（`scripts/lib-appbundle.sh`）；
缺少它时 macOS 会直接终止进程，所以这一项是必需的。

## 验证

自动检查（不需要权限、不接硬件）：

```bash
scripts/run-learning-app-tests.sh CaptureCardInputTests   # 会话/代次/不回落/旧帧/明确限制
scripts/build-app.sh                                      # arm64 + x86_64 双架构
```

真实画面离线核对（把真实画面送进**生产 OCR 与对白提取**）：

```bash
scripts/run-capture-card-check.sh                                   # 默认：已验证采集帧 + 必须读到完整句
scripts/run-capture-card-check.sh offline <图片> [必须包含的子串]     # 指定别的画面
```

真实硬件探针（会使用设备并可能弹出权限提示，需显式确认）：

```bash
FY_CAPTURE_CARD_ALLOW_HARDWARE=1 scripts/run-capture-card-check.sh inspect
FY_CAPTURE_CARD_ALLOW_HARDWARE=1 scripts/run-capture-card-check.sh authorize-ui   # 弹系统提示，请点允许
FY_CAPTURE_CARD_ALLOW_HARDWARE=1 scripts/run-capture-card-check.sh capture "USB Video" 3
```

探针调用的是产品代码 `FYCaptureCardInput`，只读视频、不采音频、不截屏，
结束后记录 `session_released`；输出目录必须是 0700 私有目录，帧和状态文件为 0600。

### 两个必须知道的运行细节

1. **必须经 LaunchServices 启动**（脚本内部用 `open -W`）。直接从终端运行子进程时，
   macOS 会把 TCC 责任归到终端/父进程，探针读到的相机授权状态就不是它自己的。
2. **签名后的 bundle 不要反复重建**。ad-hoc 签名重编后 cdhash 会变，相机授权随之失效；
   脚本因此只在工具源码变化时才重建，并使用基于标识的 designated requirement。

> Vision 的 Accurate 文字识别要求调用方是有 bundle 标识、已签名的应用，
> 所以两个工具都会被装进 `.app` 再运行；`FY_CAPTURE_CARD_BUNDLE_ID` 可覆盖核对工具的标识。

## 本机实测结果（2026-10-05）

- **真实硬件取帧通过**：`capture "USB Video" 3` 记录 `state=captured_requested_frames`、
  3 张 1920×1080 帧、`received_frames=24`、`stored_frames=8`、`skipped_frames=16`（限速丢弃，未排队）、
  `session_released=true`、`audio_inputs=0`、`screen_capture_used=false`，QuickTime 全程仍在运行。
  证据：`.build/capture-card-check/hardware-capture-20261005/`（含 status.json 与三帧）。
- **设备列表只列采集卡**：`inspect` 只返回 `USB Video`；同一台机器上原本会出现在外接列表里的
  「iPhone 相机」被类型＋型号/名称规则排除（对照 `.build/clean-video-probe/inspection-host.json`）。
- **权限被拒时不采集、不回退**：授权前 `capture` 记录 `capture_requires_camera_authorization`、
  `capture_started=false`、无帧。
- **真实画面 OCR 完整**：硬件刚取的帧经生产 OCR 读出 14 行完整日文（含 `乗り気じゃないときに`、
  `ムリしても失敗するだけ。` 等，无缺字），日志 `.build/capture-card-check/hardware-frame-ocr.log`；
  与现场残句同句的采集帧核对见 `.build/capture-card-check/offline-ocr-check.log`
  （完整读到「ミヨは占いに凝ってんの。」）。

## 安装与回退

安装：`scripts/install-app.sh`（会先退出正在运行的译芽，并把旧包备份到 `.build/app-backups/`）。

回退到旧版本：把「识别输入源」切回**窗口截图**即可立即回到原行为；
要整体退回旧构建，退出译芽后把 `.build/app-backups/译芽.app.bak.*` 复制回 `~/Applications/译芽.app`
并重新打开。学习数据库和设置不随版本切换改变。
