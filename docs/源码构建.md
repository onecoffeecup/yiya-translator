# 从源码构建译芽

适用于 0.2.1。源码附件为 `fuyi-source-0.2.1.zip`；构建包含 Sparkle 更新组件，普通构建不需要维护者发布私钥。

## 本机维护目录

唯一维护源码位于维护者工作区根目录下的 `.build/yiya-translator-publish-ocj99vs_/fuyi-0.1.0`，目录名沿用历史名称，归档时实际版本为 0.2.0。原根目录旧副本已于 2026-10-08 移入 `.archive/legacy-root-20261008/repository/`，停止同步、开发、构建和发布；归属与恢复规则见 [维护与归档约定](project-maintenance.md)。进入唯一维护仓库后再运行以下命令，其他机器使用本仓库的实际克隆目录。外部下载源码仍以包内 `VERSION` 和发布校验值为准；归档操作不更新已安装应用或公开附件。

专项实现与检查命令见 [界面 OCR 稳定说明](inline-ocr-stability.md)。

## 环境

- macOS 13+，Apple Silicon 或 Intel。
- Xcode Command Line Tools，提供 clang、SDK、lipo、codesign 等；未安装时运行 `xcode-select --install` 并完成系统安装提示。
- Python 3.9+。普通构建和资料安装仅使用标准库；重新生成图标才需要 Pillow，现成图标已提供。
- 构建会自动下载锁定的 Sparkle 2.10.0，校验 SHA-256 与上游签名，缓存位于 `~/Library/Caches/com.nanami.fuyi-build/`。普通构建无需维护者更新私钥；维护者签名发布的额外工具及流程见 [自动更新说明](automatic-updates.md)。

在源码根目录执行以下命令。下载的源码压缩包解压后，先进入 `fuyi-0.2.1` 文件夹。本机已有仓库目录可能沿用旧名称，目录名不代表源码版本；以 `VERSION`、Git提交和实际App构建号为准。

## 安装匹配的词典快照

数据库约 154 MiB，源码仓库中只保留来源、许可证和 SHA-256 校验清单。请从与源码对应的 Release 下载 `fuyi-reference-20261004.zip`：

```bash
python3 scripts/reference-data.py install "$HOME/Downloads/fuyi-reference-20261004.zip"
python3 scripts/reference-data.py check
```

安装器会核对完整文件清单、逐文件 SHA-256 和 SQLite 完整性，校验通过后才写入 `resources/learning/reference`。它不会访问用户的学习数据库。不要用其他版本资料包绕过校验。

## 构建、检查和本机安装

```bash
scripts/build-app.sh
scripts/run-checks.sh
scripts/install-app.sh
open "$HOME/Applications/译芽.app"
```

默认构建 arm64 + x86_64。只做本机快速构建时可以运行 `ARCHS=arm64 scripts/build-app.sh` 或 `ARCHS=x86_64 scripts/build-app.sh`。最低系统目标默认 13.0。

安装脚本会退出运行中的译芽、备份旧 App 并安装到 `~/Applications`。产物在 `dist/译芽.app` 时仍是组装中间产物，使用安装脚本完成本机签名。

测试会创建独立的临时数据并使用模拟 API 请求。测试输出位于 `.build/test-results/`，不会作为源码或用户资料发布。自动化测试不等于真实采集卡、多屏、全屏或新机器安装验收。

发布前须按 [Debug 工作流](../DEBUG_WORKFLOW.md) 用发布版优化等级跑一次完整核心检查：

```bash
FY_OPT=-O2 python3 scripts/debug.py check
```

核心入口调用的编译脚本及 `run-learning-app-tests.sh`、`run-tests.sh`、`run-replay-tests.sh`、`run-module-tests.sh` 均透传 `FY_OPT`，未设置时仍用 `-O0`；专门验证发布配置的 `LayoutDebugReleaseTests` 始终用 `-O2`。离线采集卡核对工具的缓存也区分优化等级，避免复用旧的 `-O0` 二进制。

核心检查不运行桌面套件。安排桌面测试时段后，还需用 `FY_OPT=-O2 FY_TEST_ALLOW_UI=1 scripts/run-learning-app-tests.sh <套件名>` 实际运行 `MainWindowResizeTests`、`InlineAdaptiveLayoutTests`、`InlineAdaptiveAcceptanceTests` 和 `CaptureMappingTests`；仅编译不算通过。优化下失败时保留断言，先补最小复现并定位根因。

2026-10-11 本机检查记录：完整 `-O2` 核心检查为 166 项通过；上述桌面套件中三组通过，[贴译验收](../tests/InlineAdaptiveAcceptanceTests.m) 为 167 通过、2 失败。两条失败均属于 `TestDegradationChain` 的同一 520×170 pt 合成画面：旧断言要求紧凑入口，当前实现按高度上限显示 93.5 pt 滚动卡，`-O0` 也得到相同结果。用户查看示意图后确认沿用当前显示，保留布局、断言及失败记录；这两条是旧验收预期与已确认行为的差异，不能为使旧验收通过而改变显示或将桌面验收记为全部通过。决定与示意图见 [小画面中的滚动卡片](subtitle-appearance.md#小画面中的滚动卡片)。缺失的真实 OCR 夹具分支及真实设备未验证。

单独运行某组测试：

```bash
scripts/run-tests.sh
scripts/run-learning-tests.sh
scripts/run-learning-app-tests.sh ReferenceDictionaryTests
scripts/run-learning-app-tests.sh CollectionLayoutTests
```

## 更新离线资料（维护者）

`scripts/import-reference-data.py --download` 从上游下载资料，并在本机 `.build` 中缓存。重新生成后需重新检查来源许可、例句署名与等级匹配，再运行 `python3 scripts/reference-data.py create-lock` 登记新快照。提交新的来源及校验清单，并为该源码版本发布新的资料附件。

`create-lock` 会接受当前资料生成新的校验值，因此它属于维护流程，不是下载资料校验失败后的修复方法。
