# API Key 本机保存约定

用户确认日期：2026-10-07。此约定适用于后续重构、构建、安装和发布；用户新的明确要求优先。

## 保存位置与访问

每位玩家在「翻译服务」填写自己的 API Key，自动保存到该玩家当前 macOS 账户的文件：

```text
~/Library/Application Support/com.nanami.fuyi/credentials/api-key.json
```

凭据目录权限为 `0700`，文件权限为 `0600`。这是本机 JSON 文件，未进行磁盘内容加密；输入框掩码不代表文件加密。文件位于源码和 `.app` 包之外，不因替换应用包而被删除。实现为 [FYLocalAPIKeyStore.h](../objc/FYLocalAPIKeyStore.h)。

不使用 Keychain 保存或读取 API Key；普通启动不请求电脑密码或钥匙串授权。不从遗留钥匙串记录恢复 Key。

## 哪些操作需要重新填写

| 操作 | 已保存 Key 的行为 |
| --- | --- |
| 退出并重新打开同一版本 | 自动读取，无需重新填写 |
| 重建或增加 build number | 自动读取，无需重新填写 |
| 重装或重新下载相同应用版本 | 自动读取，无需重新填写 |
| 从 `0.2.0` 升级到 `0.3.0` 等不同应用版本 | 新版本要求填写一次，此后自动读取 |
| 玩家主动点击「清空」 | 删除凭据文件，下次使用需填写 |

版本身份只使用 `CFBundleShortVersionString`，不得包含 `CFBundleVersion`、代码哈希、构建时间或安装路径。读取时兼容短暂使用过的 `版本/build` 记录格式，但不能跨应用版本复用 Key。版本不匹配时不使用旧 Key；重新填写成功后，以当前版本和新 Key 原子替换文件。

保存失败时保留之前的文件并显示错误，不把内存值标记为已保存，也不把 Key 回退保存到普通偏好设置。普通设置保存、退出和未填写状态不得误删原文件。

## 分发与诊断

- 每个 macOS 账户使用自己的文件，作者的 Key 不作为默认值提供给其他玩家。
- 真实 Key 和凭据文件不得进入 Git、源码包、`.app` 包、发布压缩包、其他发布附件、日志、诊断包或截图。`.gitignore` 和源码导出脚本应排除 `api-key.json`；应用组装不能收录用户应用数据目录。
- Key 仅作为认证信息发送给玩家在应用中配置的翻译服务，不发送给作者、反馈邮箱或其他玩家。
- 文档和测试只使用占位文本或合成 Key。真实 Key 的验证仅输出“已配置／读取成功／测试成功”等状态及文件权限，不能输出内容。

## 验证依据

[LocalAPIKeyStoreTests.m](../tests/LocalAPIKeyStoreTests.m) 覆盖文件权限、重复读取、应用版本切换、旧记录格式兼容、失败保留和清空；[LocalCredentialSettingsTests.m](../tests/LocalCredentialSettingsTests.m) 覆盖设置保存及重复启动读取，并隔离真实凭据和网络。

2026-10-07 本机验证：用户填写一次后，同一可执行文件第二、第三次启动均无电脑密码框，翻译测试成功；随后从 `0.2.0 build 12` 重建并安装到 `build 13`，Key 保留且实时翻译返回成功。安装包检查未发现凭据文件，可执行文件不调用 Keychain 项目存取接口。此记录仅代表本机验证。
